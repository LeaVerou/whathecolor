# What the color? 🎨

A color guessing game for CSS developers. A random color appears; type any CSS color
(`rgb()`, `hsl()`, `oklch()`, named colors, `#hex`, …) to match it as closely as you can.
Proximity is measured with [Color.js](https://colorjs.io)’s OKLab ΔE, and your score
(time + attempts per color) is kept across sessions.

Live at [whathecolor.com](https://whathecolor.com).

## Architecture

A small [Vue 3](https://vuejs.org) app with **no build step**. Dependencies are vendored
locally and wired up with an import map generated by [nudeps](https://www.npmjs.com/package/nudeps),
so the source runs directly in the browser. This mirrors the setup of
[zoelearns.com](https://github.com/LeaVerou/zoelearns.com).

```
index.html          Root component template (the app mounts on <body>)
index.js            createApp(): game state, the round/win loop, the clock
importmap.js        Generated by nudeps — maps "vue" / "colorjs.io" to client_modules/
style.css           Global layout + @imports each component’s CSS

lib/                Framework-agnostic model layer
  round.js          Round: target + guesses → proximity, ΔE, gradient, unique guesses
  timer.js          Timer: an elapsed-time value object (formats mm:ss.d)
  hint.js           getHint(): builds the live CSS-syntax hint from Color.js space metadata
  local.js          Vue mixin: persist data paths to localStorage

components/          Presentational Vue components (each with a sibling .css)
  color-board.js    Target + your-guess swatches and the proximity badge
  guess-input.js    The input: parses each keystroke, shows validity + syntax hint
  progression.js    Strip of every guess so far, plus attempt counters
  history-panel.js  Score panel: per-color cards, aggregate stats, share button
```

### Data model

The mutable game state lives in `index.js` as plain reactive data: the `solution` and the
list of valid `attempts` (both CSS strings), the elapsed time, and the persisted `history`.
Everything derived — proximity, the “your color” swatch, the progression strip, win
detection — comes from a `round` computed that wraps the state in a `Round` (see
[lib/round.js](lib/round.js)). `Round` is recreated whenever its inputs change and only ever
exposes primitives, so live `Color` objects never end up inside Vue’s reactivity system.

`Color` objects are not stored in reactive state; guesses are kept as the strings the user
typed and re-parsed on demand. This keeps state serializable (for `localStorage`) and avoids
proxy-wrapping Color.js internals.

## Development

Requires Node. Install dependencies and generate the import map:

```sh
npm install      # installs into node_modules + devDeps (nudeps)
npm run build    # runs nudeps: vendors deps into client_modules/ and writes importmap.js
```

Then serve the folder statically (any static server works) and open `index.html`.

`npm run build` is the only build step, and it just vendors dependencies — there is no
source compilation. Its outputs (`client_modules/`, `importmap.js`) and `node_modules/` are
all generated and git-ignored, so run it after cloning and whenever you add or upgrade a
dependency in `package.json`. (Your deploy should run it too.)

## Browser support

Targets modern evergreen browsers (latest Chrome, Safari, Firefox). The styles use native
CSS nesting and other Baseline features directly, with no PostCSS or other build step.
